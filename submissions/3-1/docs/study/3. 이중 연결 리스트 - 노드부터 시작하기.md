# 3. 이중 연결 리스트 - 노드부터 시작하기

## 학습 목표

- 노드(Node)가 무엇인지 설명할 수 있다.
- 연결 리스트가 배열 기반 목록과 어떻게 다른지 설명할 수 있다.
- 단일 연결 리스트와 이중 연결 리스트의 차이를 설명할 수 있다.
- 이중 연결 리스트에서 삽입, 삭제, 이동이 빠른 이유를 설명할 수 있다.
- Mini Redis가 LRU를 구현할 때 이중 연결 리스트를 사용하는 이유를 설명할 수 있다.

---

## 1. 데이터를 여러 개 저장하는 방법

프로그램은 여러 개의 데이터를 저장해야 한다. 가장 익숙한 방식은 번호가 붙은 칸에 데이터를 넣는 방식이다.

```text
인덱스     0          1        2
데이터  [Alice]    [Bob]   [Charlie]
```

이 방식은 `0번`, `1번`, `2번`처럼 번호를 알면 원하는 칸으로 바로 갈 수 있다.

하지만 중간 데이터를 삭제하거나, 중간 데이터를 맨 앞으로 옮길 때는 뒤쪽 데이터의 위치를 바꿔야 할 수 있다.

```text
삭제 전: [Alice] [Bob] [Charlie]
Bob 삭제: [Alice]        [Charlie]
정리 후: [Alice] [Charlie]
```

연결 리스트는 데이터를 번호가 붙은 칸에만 의존해 보관하지 않는다. 대신 각 데이터가 **다음 데이터가 어디에 있는지** 알려 주도록 연결한다.

| 방식 | 잘하는 일 | 불리한 일 |
| --- | --- | --- |
| 배열/일반 목록 | 번호(인덱스)로 바로 접근 | 중간 삽입·삭제 시 뒤쪽 데이터를 옮길 수 있음 |
| 연결 리스트 | 이미 찾은 위치에서 삽입·삭제·이동 | n번째 데이터를 바로 찾기 어려움 |

이중 연결 리스트는 특히 "최근 사용한 데이터를 맨 앞으로 옮기기" 같은 작업에 적합하다.

---

## 2. 노드(Node)란?

**노드**는 데이터를 저장하는 작은 상자다.

```text
[ data: Alice ]
```

연결 리스트의 노드는 데이터만 저장하지 않는다. 다른 노드와 연결하기 위한 정보도 함께 저장한다.

단일 연결 리스트의 노드는 보통 다음 노드를 가리킨다.

```text
[ data: Alice | next: Bob 노드의 위치 ]
```

이중 연결 리스트의 노드는 이전과 다음 노드를 모두 가리킨다.

```text
[ prev: 이전 노드 | data: Alice | next: 다음 노드 ]
```

이 프로젝트의 `Node` 클래스도 아래 세 필드를 가진다.

| 필드 | 의미 |
| --- | --- |
| `data` | 실제로 저장할 데이터 |
| `prev` | 이전 노드 |
| `next` | 다음 노드 |

> 노드는 단순한 값이 아니라, 값과 다른 노드로 이어지는 연결 정보를 함께 가진 객체다.

---

## 3. 연결 리스트(Linked List)란?

노드를 순서대로 연결한 자료구조를 연결 리스트라고 한다.

```text
[Alice] -> [Bob] -> [Charlie] -> None
```

위 그림에서는 다음과 같이 동작한다.

- `Alice` 노드는 다음 노드가 `Bob`임을 안다.
- `Bob` 노드는 다음 노드가 `Charlie`임을 안다.
- `Charlie` 뒤에는 더 이상 노드가 없으므로 `None`을 가리킨다.

어떤 데이터를 찾으려면 첫 번째 노드부터 `next`를 따라가며 하나씩 확인해야 한다.

```text
Alice 찾기: 첫 번째 노드에서 발견
Charlie 찾기: Alice -> Bob -> Charlie 순서로 이동
```

따라서 특정 값을 찾는 작업은 보통 O(n)이다.

---

## 4. 단일 연결 리스트와 이중 연결 리스트

### 4.1 단일 연결 리스트

단일 연결 리스트는 각 노드가 다음 노드만 안다.

```text
None -> [Alice] -> [Bob] -> [Charlie] -> None
```

`Bob`을 삭제하려면 `Bob`의 이전 노드인 `Alice`가 필요하다. 그래야 `Alice.next`를 `Charlie`로 바꿀 수 있다.

```text
삭제 전: [Alice] -> [Bob] -> [Charlie]
삭제 후: [Alice] ------------> [Charlie]
```

하지만 `Bob`은 이전 노드가 누구인지 직접 알지 못한다. 따라서 이전 노드를 찾기 위해 처음부터 순회해야 할 수 있다.

### 4.2 이중 연결 리스트

이중 연결 리스트는 각 노드가 이전과 다음 노드를 모두 안다.

```text
None <-> [Alice] <-> [Bob] <-> [Charlie] <-> None
```

`Bob` 노드는 다음 정보를 이미 갖고 있다.

```text
Bob.prev = Alice
Bob.next = Charlie
```

그래서 `Bob`을 삭제할 때는 `Alice`와 `Charlie`을 바로 연결하면 된다.

```text
삭제 전: [Alice] <-> [Bob] <-> [Charlie]
삭제 후: [Alice] <------------> [Charlie]
```

| 비교 | 단일 연결 리스트 | 이중 연결 리스트 |
| --- | --- | --- |
| 노드가 아는 연결 | 다음 노드 | 이전 노드와 다음 노드 |
| 뒤로 이동 | 어려움 | 가능 |
| 이미 찾은 중간 노드 삭제 | 이전 노드를 찾아야 할 수 있음 | O(1) |
| 노드당 연결 정보 | 1개 | 2개 |

이중 연결 리스트는 연결 정보를 하나 더 저장하는 대신, 중간 노드의 삭제와 위치 변경을 쉽게 만든다.

---

## 5. 센티널 노드(head, tail)

이 프로젝트의 연결 리스트는 실제 데이터 앞뒤에 특별한 노드를 둔다.

```text
head <-> [Alice] <-> [Bob] <-> tail
```

`head`와 `tail`은 실제 데이터를 저장하지 않는 **센티널 노드(sentinel node)**다.

빈 리스트도 같은 모양으로 표현할 수 있다.

```text
head <-> tail
```

센티널 노드를 두면 "리스트가 비어 있다", "첫 번째 데이터를 추가한다", "마지막 데이터를 제거한다" 같은 상황을 더 일정한 방식으로 처리할 수 있다.

예를 들어 맨 앞에 새 노드를 추가할 때는 항상 `head` 바로 뒤에 넣으면 된다.

```text
추가 전: head <-> [Alice] <-> tail
추가 후: head <-> [Bob] <-> [Alice] <-> tail
```

---

## 6. 핵심 연산은 어떻게 동작할까?

### 6.1 맨 앞 삽입: `insert_front`

새 노드를 `head`와 기존 첫 번째 노드 사이에 연결한다.

```text
추가 전: head <-> [Alice] <-> tail
추가 후: head <-> [Bob] <-> [Alice] <-> tail
```

새 노드 `Bob`에 대해 필요한 연결은 다음과 같다.

```text
Bob.prev = head
Bob.next = Alice
head.next = Bob
Alice.prev = Bob
```

첫 번째 노드만 알고 있으면 되므로 O(1)이다.

### 6.2 맨 뒤 삽입: `insert_back`

새 노드를 기존 마지막 노드와 `tail` 사이에 연결한다.

```text
추가 전: head <-> [Alice] <-> tail
추가 후: head <-> [Alice] <-> [Bob] <-> tail
```

`tail.prev`로 마지막 실제 노드를 바로 알 수 있으므로 O(1)이다.

### 6.3 특정 노드 삭제: `remove_node`

이미 `Bob` 노드를 알고 있다고 가정하자.

```text
삭제 전: [Alice] <-> [Bob] <-> [Charlie]
삭제 후: [Alice] <------------> [Charlie]
```

필요한 작업은 두 번의 연결 변경이다.

```text
Alice.next = Charlie
Charlie.prev = Alice
```

그다음 삭제된 `Bob`의 `prev`, `next`를 비워 두면, 더 이상 리스트에 연결되지 않았다는 것을 명확히 할 수 있다.

> `remove_node`가 O(1)인 이유는 **삭제할 노드를 이미 알고 있기 때문**이다. 값만 알고 노드를 찾아야 한다면 먼저 순회해야 하므로 O(n)이다.

### 6.4 맨 앞으로 이동: `move_to_front`

`Bob`을 맨 앞으로 옮기는 일은 두 단계다.

```text
처음: head <-> [Alice] <-> [Bob] <-> [Charlie] <-> tail
1단계: Bob을 현재 위치에서 분리
2단계: Bob을 head 바로 뒤에 연결
결과: head <-> [Bob] <-> [Alice] <-> [Charlie] <-> tail
```

분리와 삽입 모두 주변 노드만 바꾸므로, `Bob` 노드를 알고 있다면 O(1)이다. 노드 수는 바뀌지 않으므로 리스트의 크기도 변경하지 않는다.

## 7. 시간 복잡도 정리

| 작업 | 시간 복잡도 | 이유 |
| --- | --- | --- |
| 맨 앞 삽입 | O(1) | `head` 바로 뒤만 연결 |
| 맨 뒤 삽입 | O(1) | `tail.prev`와 `tail` 사이만 연결 |
| 맨 앞/뒤 삭제 | O(1) | 첫 번째 또는 마지막 노드를 바로 앎 |
| 이미 알고 있는 노드 삭제 | O(1) | `prev`, `next`를 바로 사용 |
| 이미 알고 있는 노드를 맨 앞으로 이동 | O(1) | 분리와 재연결만 수행 |
| 특정 값을 찾기 | O(n) | 첫 노드부터 하나씩 순회 |

해시맵과 이중 연결 리스트를 함께 쓰면, 해시맵이 키로 노드를 빠르게 찾고 이중 연결 리스트가 그 노드를 빠르게 옮기거나 제거할 수 있다.

## 8. Mini Redis에서는 어떻게 사용할까?

이 프로젝트의 `mini_redis/linked_list.py`에는 `Node`와 `DoublyLinkedList`가 구현되어 있다.

| 메서드 | 역할 |
| --- | --- |
| `insert_front(data)` | 새 노드를 맨 앞에 넣음 |
| `insert_back(data)` | 새 노드를 맨 뒤에 넣음 |
| `remove_front()` | 맨 앞 노드를 제거 |
| `remove_back()` | 맨 뒤 노드를 제거 |
| `remove_node(node)` | 알고 있는 특정 노드를 제거 |
| `move_to_front(node)` | 알고 있는 노드를 맨 앞으로 이동 |

### 8.1 해시 충돌 목록

해시맵의 한 버킷에 여러 키가 들어가면, 그 키-값 엔트리들을 연결 리스트로 보관한다.

```text
bucket 3
head <-> [user:1, Alice] <-> [user:9, Diana] <-> tail
```

### 8.2 LRU 최근 사용 순서

LRU에서는 앞이 가장 최근 사용한 데이터, 뒤가 가장 오래 사용한 데이터다.

```text
가장 최근 사용                                  가장 오래 사용
head <-> [user:3] <-> [user:1] <-> [user:2] <-> tail
```

`GET user:1`이 성공하면 해시맵으로 `user:1`의 엔트리를 찾는다. 엔트리가 기억한 LRU 노드를 이용해 `user:1`을 맨 앞으로 옮긴다.

```text
GET user:1
  -> 해시맵에서 user:1 엔트리 조회
  -> 엔트리가 가진 lru_node 확인
  -> move_to_front(lru_node)
```

메모리가 부족하면 `tail` 바로 앞의 노드, 즉 가장 오래 사용하지 않은 키를 제거한다.

```text
head <-> [user:1] <-> [user:3] <-> [user:2] <-> tail
                                             ↑
                                        LRU, 제거 대상
```

이것이 해시맵과 이중 연결 리스트를 함께 사용하면 LRU 갱신과 제거를 빠르게 처리할 수 있는 이유다.

## 9. 자주 생기는 오해

### "이중 연결 리스트면 값을 바로 찾을 수 있나?"

아니다. 연결 리스트만으로 특정 값을 찾으려면 처음부터 순회해야 한다. 이 프로젝트에서는 해시맵이 키를 빠르게 찾고, 이중 연결 리스트는 찾은 노드의 순서를 관리한다.

### "삭제가 항상 O(1)인가?"

삭제할 노드 객체를 이미 알고 있을 때만 O(1)이다. `"Bob"`이라는 값만 알고 있다면 먼저 `Bob` 노드를 찾아야 하므로 O(n)이다.

### "왜 단일 연결 리스트를 쓰지 않나?"

LRU는 최근 사용한 노드를 자주 맨 앞으로 옮기고, 가장 오래된 노드를 제거한다. 이전 노드도 바로 알 수 있는 이중 연결 리스트가 이 작업을 단순하고 빠르게 만든다.

### 한 문장으로 정리
