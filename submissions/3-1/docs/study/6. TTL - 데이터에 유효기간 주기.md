# 6. TTL - 데이터에 유효기간 주기

## 학습 목표

- TTL(Time To Live)이 무엇인지 설명할 수 있다.
- `EXPIRE`와 `TTL` 명령의 동작을 설명할 수 있다.
- 만료된 키를 왜 없는 키처럼 처리하는지 설명할 수 있다.
- TTL과 LRU의 차이를 설명할 수 있다.
- 기존 키를 덮어쓰거나 삭제할 때 TTL 정보를 함께 정리해야 하는 이유를 설명할 수 있다.

---

## 1. TTL이란?

TTL은 **Time To Live**의 줄임말이다.

> 데이터가 살아 있을 수 있는 남은 시간

어떤 데이터는 영구히 보관할 필요가 없다. 일정 시간이 지나면 자동으로 사라져야 하는 데이터도 있다.

예시:

- 이메일 인증 번호: 5분 뒤 무효화
- 비밀번호 재설정 토큰: 10분 뒤 무효화
- 로그인 세션: 30분 동안 사용하지 않으면 만료
- 외부 API 캐시: 1분 뒤 새 데이터로 갱신

TTL은 키에 "언제까지 유효한가"라는 시간 제한을 붙이는 기능이다.

```text
session:abc123 -> user_id=42
유효 시간      -> 30분
```

30분이 지나면 `session:abc123`은 더 이상 존재하지 않는 키처럼 처리된다.

---

## 2. `EXPIRE`: 키에 유효기간 설정하기

다음 명령은 이미 존재하는 키에 TTL을 초 단위로 설정한다.

```text
EXPIRE user:1 10
```

뜻은 다음과 같다.

```text
user:1은 지금부터 10초 뒤에 만료된다.
```

| 상황 | 결과 |
| --- | --- |
| 키가 존재하고 `seconds > 0` | `(integer) 1`, TTL 설정 성공 |
| 키가 없음 | `(integer) 0` |
| `seconds <= 0`이고 키가 존재 | 즉시 삭제 후 `(integer) 1` |
| 초 값이 정수가 아님 | 정수 파싱 오류 |

예시:

```text
SET user:1 "Alice"
EXPIRE user:1 10
(integer) 1
```

반대로 없는 키에는 TTL을 붙일 수 없다.

```text
EXPIRE missing-key 10
(integer) 0
```

---

## 3. 만료 시각으로 생각하기

TTL은 "10초" 자체를 계속 줄여 가며 저장하지 않는다. 보통은 **언제 만료될지**를 계산해 저장한다.

```text
현재 시각: 100초
EXPIRE user:1 10

만료 시각(expire_at): 110초
```

나중에 현재 시각이 110초 이상이 되면 키는 만료된 것이다.

```text
현재 시각 < expire_at  -> 아직 유효
현재 시각 >= expire_at -> 만료
```

Mini Redis는 시스템 시각이 바뀌는 영향을 줄이기 위해 일정하게 증가하는 시간 측정값을 사용한다. 중요한 것은 시간값의 실제 숫자가 아니라, 현재 시각이 만료 시각을 지났는지 비교하는 것이다.

---

## 4. `TTL`: 남은 시간 확인하기

다음 명령은 키의 남은 유효 시간을 초 단위로 확인한다.

```text
TTL user:1
```

| 상황 | 결과 |
| --- | --- |
| 키가 존재하고 TTL이 없음 | `(integer) -1` |
| 키가 없거나 이미 만료됨 | `(integer) -2` |
| 키가 존재하고 TTL이 있음 | `(integer) N` |

예시:

```text
SET user:1 "Alice"
TTL user:1
(integer) -1

EXPIRE user:1 3
TTL user:1
(integer) 2
```

`EXPIRE user:1 3` 직후에 `TTL`이 2로 보일 수 있다. 명령 처리와 출력 사이에도 아주 짧은 시간이 지나고, Mini Redis는 남은 초의 소수점 부분을 버리기 때문이다.

```text
남은 시간: 2.8초
TTL 결과:  2
```

---

## 5. 만료된 키는 어떻게 처리할까?

키가 만료되면 값만 숨기는 것이 아니라, 저장소에서 삭제해야 한다.

```text
SET user:1 "Alice"
EXPIRE user:1 3

# 3초 뒤
GET user:1
(nil)
```

만료된 키는 다음 명령에서 없는 키처럼 동작한다.

| 명령 | 만료된 키의 처리 |
| --- | --- |
| `GET key` | 삭제 후 `(nil)` |
| `EXISTS key` | 삭제 후 `(integer) 0` |
| `DEL key` | 이미 없는 키이므로 `(integer) 0` |
| `TTL key` | 삭제 후 `(integer) -2` |

Mini Redis는 명령을 처리하기 전에 만료 시간이 지난 키를 먼저 정리한다. 또한 키를 직접 조회할 때도 한 번 더 만료 여부를 확인한다.

이 방식 덕분에 만료된 키가 LRU의 최근 사용 순서에 다시 올라가는 일이 없다.

---

## 6. TTL과 다른 명령의 관계

### 6.1 `SET`으로 덮어쓰기

기존 키에 새 값을 `SET`하면 기존 TTL은 사라진다.

```text
SET user:1 "Alice"
EXPIRE user:1 10
SET user:1 "New Alice"
TTL user:1
(integer) -1
```

이 규칙은 새 값을 저장하는 행위를 새 데이터로 취급하기 때문이다. 이전 값에 붙어 있던 만료 시간을 그대로 적용하면 새 값이 예상보다 빨리 사라질 수 있다.

### 6.2 `DEL`로 삭제

`DEL`은 데이터만 지우면 안 된다. TTL 정보도 함께 무효화해야 한다.

```text
DEL user:1
```

삭제한 뒤 나중에 이전 TTL 기록이 발견되더라도, 이미 삭제한 키를 다시 건드리면 안 된다.

### 6.3 `EXPIRE`를 다시 호출

이미 TTL이 있는 키에 다시 `EXPIRE`를 호출하면 새 만료 시각이 적용된다.

```text
EXPIRE user:1 10
EXPIRE user:1 60
```

이 경우 10초짜리 이전 기록은 오래된 기록이 된다. 이 문제는 뒤의 lazy deletion 문서에서 자세히 다룬다.

---

## 7. TTL과 LRU의 차이

TTL과 LRU는 둘 다 키를 제거하지만, 판단 기준이 다르다.

| 구분 | TTL | LRU |
| --- | --- | --- |
| 제거 기준 | 정해진 만료 시각이 지남 | 가장 오래 사용하지 않음 |
| 제거 시점 | 시간이 지났을 때 | 메모리가 부족할 때 |
| 대표 용도 | 인증 코드, 세션, 짧은 캐시 | 제한된 캐시 메모리 관리 |

```text
TTL: "약속한 시간이 지났으니 삭제한다"
LRU: "메모리가 부족하니 오래 안 쓴 것을 삭제한다"
```

둘은 함께 사용할 수 있다. 만료된 키는 먼저 TTL로 삭제하고, 남은 키들로도 메모리가 부족하면 LRU를 적용한다.

---

## 8. 이 프로젝트의 구현과 연결하기

각 `CacheEntry`에는 TTL 관련 상태가 들어 있다.

| 필드 | 역할 |
| --- | --- |
| `expire_at` | 이 시각 이후 키가 만료됨 |
| `ttl_version` | 새 TTL인지 오래된 TTL 기록인지 구별하는 번호 |

`mini_redis/store.py`의 주요 메서드는 다음과 같다.

| 메서드 | 역할 |
| --- | --- |
| `_expire(key, seconds)` | TTL 설정 또는 즉시 삭제 |
| `_ttl(key)` | 남은 시간 반환 |
| `_purge_expired()` | 만료 시각이 지난 키 정리 |
| `_live_entry(key)` | 조회 직전 만료 여부를 한 번 더 확인 |
| `_clear_ttl(entry)` | `SET` 덮어쓰기 시 기존 TTL 무효화 |
| `_delete_key(key)` | 삭제 시 데이터·LRU·TTL을 함께 정리 |

TTL을 효율적으로 확인하기 위해 Mini Redis는 다음 문서에서 다룰 최소 힙을 사용한다.

6. TTL과 LRU는 각각 어떤 기준으로 키를 제거하는가?
7. 만료된 키를 LRU 목록에서도 함께 제거해야 하는 이유는 무엇인가?

### 한 문장으로 정리

> TTL은 키에 만료 시각을 붙여 정해진 시간이 지난 데이터를 없는 키처럼 삭제하는 기능이며, Mini Redis는 `EXPIRE`, `TTL`, 만료 전 정리 과정을 통해 이를 관리한다.

다음 문서에서는 여러 TTL 중 가장 빨리 만료되는 키를 빠르게 찾기 위한 **최소 힙**을 살펴본다.
