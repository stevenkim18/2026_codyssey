# 1. Redis와 Key-Value 저장소

## 학습 목표

- Redis가 어떤 문제를 해결하는 저장소인지 설명할 수 있다.
- Key와 Value의 역할을 예시로 설명할 수 있다.
- Redis가 주로 사용되는 상황과 이 Mini Redis 과제의 범위를 구분할 수 있다.

---

## 1. Redis란?

Redis는 데이터를 **메모리(RAM)에 저장**해 매우 빠르게 읽고 쓸 수 있는 Key-Value 저장소다.

일반적인 관계형 데이터베이스는 테이블, 행, 열로 데이터를 관리한다. 반면 Redis는 보통 다음처럼 **키로 값을 바로 찾는 방식**을 사용한다.

```text
user:1  ->  Alice
user:2  ->  Bob
```

- **Key(키)**: 데이터를 찾기 위한 고유한 이름 또는 식별자
- **Value(값)**: 키에 연결해 저장하는 실제 데이터

예를 들어 아래 명령은 `user:1`이라는 키에 `Alice`라는 값을 저장한다.

```text
SET user:1 "Alice"
```

같은 키로 값을 조회할 수 있다.

```text
GET user:1
"Alice"
```

### 메모리에 저장한다는 뜻

메모리(RAM)는 디스크보다 접근 속도가 빠르다. 그래서 Redis는 짧은 시간 안에 같은 데이터를 매우 많이 조회하거나 변경해야 하는 상황에 잘 맞는다.

다만 메모리는 용량이 한정되고 비용도 크다. 따라서 Redis를 사용할 때는 어떤 데이터를 얼마나 오래 보관할지 정해야 한다. 이 과제의 `maxmemory`, LRU, TTL 기능도 이 문제를 해결하기 위한 장치다.

> 실제 Redis는 영속성 기능도 제공할 수 있지만, 이 Mini Redis 과제는 메모리 안에서만 동작하며 파일 저장과 네트워크 통신은 구현하지 않는다.

---

## 2. Redis는 주로 어디에 사용할까?

### 2.1 캐시(Cache)

캐시는 자주 필요한 결과를 잠시 저장해 두었다가 다음 요청에서 빠르게 다시 사용하는 공간이다.

```text
사용자 요청
  -> Redis에 결과가 있는지 확인
  -> 있으면 Redis 결과를 즉시 반환
  -> 없으면 DB 또는 외부 API에서 조회
  -> 조회 결과를 Redis에 저장
```

예시:

- 인기 상품 목록
- 게시글 상세 조회 결과
- 날씨, 환율, 지도 같은 외부 API 응답

매번 데이터베이스나 외부 API를 호출하지 않아도 되므로 응답 시간이 줄고 원본 시스템의 부담도 줄어든다.

### 2.2 로그인 세션과 인증 정보

사용자가 로그인한 상태, 이메일 인증 번호, 비밀번호 재설정 토큰은 대개 영구 보관할 필요가 없다. 일정 시간이 지나면 자동으로 사라져야 한다.

```text
session:abc123  ->  user_id=42
reset-token:xyz ->  user_id=42
```

이때 TTL(Time To Live)을 사용하면 "10분 뒤 자동 삭제" 같은 규칙을 만들 수 있다.

### 2.3 조회 수와 카운터

짧은 시간에 숫자가 자주 바뀌는 데이터도 Redis에 잘 맞는다.

예시:

- 현재 접속자 수
- 게시글 조회 수
- 좋아요 수
- 재고 알림 신청 수

이 Mini Redis는 String 명령만 구현하지만, 실제 Redis는 숫자를 증가시키는 전용 명령도 제공한다.

### 2.4 요청 횟수 제한(Rate Limiting)

특정 사용자가 API나 로그인 기능을 너무 자주 호출하지 못하게 제한하는 기능이다.

예를 들어 "1분 동안 로그인 시도는 5번까지"라는 규칙을 만들 수 있다.

```text
login-attempt:user:42 -> 3
```

이 키에 TTL을 함께 설정하면 1분이 지난 뒤 자동으로 카운터가 초기화된다.

### 2.5 실시간 상태와 메시지 처리

Redis는 빠른 읽기·쓰기 특성 때문에 다음과 같은 실시간 기능에도 사용된다.

- 채팅방의 최근 메시지
- 현재 온라인인 사용자 목록
- 게임 랭킹과 실시간 순위
- 알림이나 백그라운드 작업 대기열

이 Mini Redis는 네트워크, Pub/Sub, 복잡 자료형을 구현하지 않는다. 하지만 현재 만드는 해시맵, 연결 리스트, 힙은 이런 기능을 확장할 때도 기반이 된다.

## 3. 일반 데이터베이스와 Redis의 역할 차이

| 구분 | Redis | 관계형 데이터베이스 예: MySQL, PostgreSQL |
| --- | --- | --- |
| 주요 데이터 모델 | Key-Value | 테이블, 행, 열, 관계 |
| 주 저장 위치 | 메모리(RAM) | 주로 디스크 |
| 강점 | 매우 빠른 읽기·쓰기 | 복잡한 검색, 관계, 영구 보관 |
| 대표 역할 | 캐시, 세션, 실시간 상태 | 서비스의 핵심 영구 데이터 |

Redis는 보통 관계형 데이터베이스를 완전히 대체하기보다, 앞단에서 속도를 높이거나 일시적인 상태를 관리하는 **보조 저장소**로 사용한다.

예를 들어 쇼핑몰의 주문 정보는 데이터베이스에 영구 저장하고, 인기 상품 목록처럼 자주 조회되는 결과는 Redis에 잠시 저장할 수 있다.

## 4. 이 Mini Redis 과제와 연결하기

이 과제는 실제 Redis의 모든 기능을 만들지 않는다. 대신 Redis가 빠르게 동작하는 핵심 원리를 직접 구현한다.

| 실제 Redis에서 다루는 문제 | Mini Redis에서 구현하는 방식 |
| --- | --- |
| 키로 값을 빠르게 찾기 | 직접 구현한 해시맵 |
| 최근 사용 순서 관리 | 이중 연결 리스트 |
| 메모리가 부족할 때 오래된 데이터 제거 | LRU 정책 |
| 일정 시간이 지난 데이터 삭제 | TTL + 최소 힙 |
| 사용자와 명령을 주고받기 | CLI REPL |

다음 명령 하나에도 여러 개념이 함께 동작한다.

```text
SET user:1 "Alice"
```

1. CLI가 명령어와 인자를 파싱한다.
2. 해시맵에 `user:1` 키와 `Alice` 값을 저장한다.
3. LRU 연결 리스트에서 이 키를 가장 최근 사용 위치로 옮긴다.
4. `len(utf8(key)) + len(utf8(value))`만큼 `used_memory`를 갱신한다.
5. `maxmemory`를 넘었다면 가장 오래 사용하지 않은 키부터 제거한다.

## 5. 핵심 용어 정리

| 용어 | 쉬운 설명 |
| --- | --- |
| Key-Value | 이름표(Key)에 데이터(Value)를 연결해 저장하는 방식 |
| In-Memory | 데이터를 디스크가 아니라 메모리에 두는 방식 |
| 캐시 | 나중에 빠르게 재사용하려고 결과를 잠시 보관하는 공간 |
| TTL | 데이터가 살아 있는 남은 시간 |
| LRU | 가장 오래 사용하지 않은 데이터를 먼저 제거하는 정책 |
| maxmemory | Redis가 사용할 수 있는 최대 메모리 크기 |
| eviction | 메모리 제한을 지키기 위해 데이터를 자동으로 제거하는 일 |

### 한 문장으로 정리

> Redis는 키를 이용해 값을 빠르게 저장하고 조회하는 메모리 기반 Key-Value 저장소이며, 캐시·세션·카운터·실시간 상태처럼 빠른 처리가 필요한 데이터에 주로 사용된다.
