# TaskFlow PRD

## 1. 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서명 | TaskFlow 제품 요구사항 정의서 |
| 프로젝트 유형 | 개인용 프로젝트·할 일 관리 웹 서비스 |
| 문서 상태 | 구현 기준 확정 |

| 작성 기준 | React SPA와 CRUD 학습 |

## 2. 제품 한 줄 소개

TaskFlow는 사용자가 프로젝트를 만들고, 프로젝트 안에 할 일을 등록하여 상태·우선순위·마감일을 관리할 수 있는 개인용 생산성 서비스입니다.

## 3. 배경과 문제 정의

할 일과 프로젝트를 메모장이나 여러 앱에 나누어 기록하면 다음과 같은 문제가 생깁니다.

- 어떤 프로젝트에 속한 일인지 알기 어렵다.
- 아직 하지 않은 일과 완료한 일을 구분하기 어렵다.
- 중요한 일과 급하지 않은 일이 섞인다.
- 마감일이 있는 작업을 놓치기 쉽다.
- 진행 상황을 한눈에 확인하기 어렵다.

TaskFlow는 프로젝트와 할 일을 하나의 흐름으로 연결하여 개인의 작업을 간단하게 정리하는 것을 목표로 합니다.

## 4. 목표 사용자

### 주요 사용자

- 혼자 공부하거나 개인 프로젝트를 진행하는 학습자
- 업무나 생활 속 할 일을 정리하려는 개인 사용자
- 복잡한 협업 기능 없이 자신의 작업만 관리하고 싶은 사용자

### 사용자의 기본 상황

사용자는 회원가입 후 로그인합니다. 프로젝트를 만들고, 해당 프로젝트에 할 일을 추가합니다. 할 일의 상태와 우선순위를 변경하고, 마감일을 확인하면서 작업을 진행합니다.

## 5. 제품 목표

### 핵심 목표

1. 사용자가 자신의 프로젝트를 생성하고 관리할 수 있습니다.
2. 사용자가 프로젝트에 할 일을 추가하고 관리할 수 있습니다.
3. 사용자가 할 일의 진행 상태를 쉽게 변경할 수 있습니다.
4. 사용자가 우선순위와 마감일을 기준으로 중요한 작업을 확인할 수 있습니다.
5. React의 사용자 이벤트 → 상태 변경 → 화면 렌더링 흐름을 명확하게 보여줍니다.

### 성공 기준

- 회원가입과 로그인이 정상적으로 동작합니다.
- 로그인한 사용자는 자신의 데이터만 볼 수 있습니다.
- 프로젝트는 생성·조회·수정·보관이 동작하고, 할 일은 생성·조회·수정·삭제가 동작합니다.
- 과제의 핵심 CRUD 데이터는 할 일(Task)입니다.
- 할 일 상태 변경이 화면에 즉시 반영됩니다.
- 로딩·에러·빈 상태가 사용자에게 표시됩니다.
- 배포 URL에서 핵심 흐름이 동작합니다.

## 7. 정보 구조

서비스의 데이터 관계는 다음과 같습니다.

    사용자
    └── 여러 프로젝트
        └── 여러 할 일

한 사용자는 여러 프로젝트를 가질 수 있고, 하나의 프로젝트에는 여러 할 일이 포함됩니다. 프로젝트와 할 일은 모두 로그인한 사용자에게 연결됩니다.

## 9. 세부 동작 규칙

### 핵심 CRUD 기준

이번 과제의 핵심 CRUD 데이터는 Task입니다.

- Project는 할 일을 묶는 보조 데이터입니다.
- Project는 생성·조회·수정·보관을 지원합니다.
- Task는 생성·조회·수정·삭제를 모두 지원합니다.
- Project를 삭제하지 않고 보관 상태로 숨깁니다.

### 프로젝트 보관

- 보관된 프로젝트는 기본 프로젝트 목록에서 숨깁니다.
- 보관된 프로젝트와 그 안의 Task는 삭제하지 않습니다.
- 필요하면 보관된 프로젝트 보기에서 확인할 수 있습니다.
- MVP에서는 프로젝트 보관 해제 기능을 생략할 수 있습니다.

### Task 상태와 우선순위

- 상태는 할 일(todo), 진행 중(in_progress), 완료(done) 세 가지입니다.
- 우선순위는 낮음(low), 보통(medium), 높음(high) 세 가지입니다.
- 상태와 우선순위는 선택형 입력으로 제공합니다.
- 상태와 우선순위 필터를 모두 선택하면 AND 조건으로 적용합니다.

### 프로젝트 진행률

프로젝트 진행률은 다음 공식으로 계산합니다.

    완료된 Task 수 / 전체 Task 수 × 100

Task가 하나도 없는 프로젝트는 숫자 대신 “아직 할 일이 없습니다.”를 표시합니다.

### 마감일

- 마감일은 시간 없이 날짜만 저장합니다.
- 오늘보다 이전이고 완료되지 않은 Task는 지연 상태로 표시합니다.
- 오늘 마감인 미완료 Task는 강조 표시합니다.
- 완료된 Task는 마감일이 지나도 지연 상태로 표시하지 않습니다.

### 프로젝트 색상

프로젝트 색상은 자유로운 색상 코드 입력 대신 미리 정한 선택지에서 고릅니다.

- blue
- green
- yellow
- red
- purple
- gray

### 보호 라우트

로그인해야 접근할 수 있는 라우트는 다음과 같습니다.

- /dashboard
- /projects
- /projects/new
- /projects/:id
- /projects/:id/edit
- /projects/:id/tasks/new
- /tasks/:id
- /tasks/:id/edit

비로그인 사용자가 보호 라우트에 접근하면 /login으로 이동합니다. 로그인한 사용자가 /login 또는 /signup에 접근하면 /dashboard로 이동합니다.

## 11. 사용자 흐름

### 11.1 회원가입 흐름

    회원가입 페이지 접속
      ↓
    이메일·비밀번호 입력
      ↓
    필수값과 비밀번호 형식 검증
      ↓
    회원가입 요청 중 버튼 비활성화
      ↓
    Supabase Auth 회원가입
      ↓
    이메일 인증 없이 성공하면 대시보드로 이동
      ↓
    실패하면 폼에 에러 메시지 표시

### 11.2 로그인 흐름

    로그인 페이지 접속
      ↓
    이메일·비밀번호 입력
      ↓
    로그인 요청
      ↓
    성공하면 대시보드로 이동
      ↓
    실패하면 로그인 실패 메시지 표시

### 11.3 프로젝트 생성 흐름

    프로젝트 목록에서 새 프로젝트 버튼 클릭
      ↓
    프로젝트 생성 폼 표시
      ↓
    이름 입력 및 필수값 검증
      ↓
    Supabase에 프로젝트 저장
      ↓
    성공하면 프로젝트 상세 또는 목록으로 이동

### 11.4 할 일 생성 흐름

    프로젝트 상세에서 할 일 추가 버튼 클릭
      ↓
    제목·설명·상태·우선순위·마감일 입력
      ↓
    제목 필수값 검증
      ↓
    Supabase에 project_id와 함께 저장
      ↓
    성공하면 프로젝트의 할 일 목록 갱신

### 11.5 할 일 상태 변경 흐름

    상태 변경 버튼 또는 선택 메뉴 클릭
      ↓
    상태를 todo / in_progress / done 중 하나로 변경
      ↓
    Supabase 데이터 갱신
      ↓
    카드의 상태 배지와 진행률 즉시 변경

## 12. 페이지 요구사항

### /

- 서비스 이름과 간단한 설명을 보여줍니다.
- 로그인 상태에 따라 대시보드 또는 로그인 페이지로 이동할 수 있습니다.

### /login

- 이메일 입력
- 비밀번호 입력
- 로그인 버튼
- 회원가입 페이지 이동 링크
- 로그인 실패 메시지
- 제출 중 상태

### /signup

- 이메일 입력
- 비밀번호 입력
- 비밀번호 확인 입력
- 회원가입 버튼
- 필수값 및 비밀번호 일치 검증
- 회원가입 실패 메시지
- 로그인 페이지 이동 링크

### /dashboard

- 전체 프로젝트 수
- 전체 할 일 수
- 완료한 할 일 수
- 오늘 또는 마감일이 가까운 할 일
- 최근 프로젝트 목록
- 프로젝트 목록으로 이동하는 링크

### /projects

- 프로젝트 목록
- 새 프로젝트 버튼
- 보관된 프로젝트 숨김 또는 표시
- 프로젝트가 없을 때 빈 상태
- 조회 중 로딩 상태
- 조회 실패 에러 상태

### /projects/new

- 프로젝트 이름 입력
- 프로젝트 설명 입력
- 프로젝트 색상 선택
- 프로젝트 생성 버튼
- 이름 필수값 검증
- 저장 중 상태

### /projects/:id

- 프로젝트 이름과 설명
- 프로젝트 보관·삭제 또는 수정 버튼
- 프로젝트 진행률
- 해당 프로젝트의 할 일 목록
- 새 할 일 버튼
- 상태·우선순위 필터
- 할 일이 없을 때 빈 상태

### /projects/:id/edit

- 기존 프로젝트 정보가 입력된 폼
- 프로젝트 이름·설명·색상 수정
- 저장 중 상태
- 저장 성공 후 프로젝트 상세로 이동

### /projects/:id/tasks/new

- 제목 입력
- 설명 입력
- 상태 선택
- 우선순위 선택
- 마감일 선택
- 필수값 검증
- 저장 중 상태

### /tasks/:id

- 할 일 제목과 설명
- 프로젝트 이름
- 상태 배지
- 우선순위 배지
- 마감일
- 수정 버튼
- 삭제 버튼
- 로딩·에러·존재하지 않는 데이터 상태

### /tasks/:id/edit

- 기존 할 일 정보가 입력된 폼
- 제목·설명·상태·우선순위·마감일 수정
- 저장 성공 후 상세 페이지 이동

### *

- 존재하지 않는 주소라는 안내
- 홈 또는 대시보드로 돌아가는 링크

## 13. 기능 요구사항과 수용 기준

### 인증

#### 회원가입

- 이메일과 비밀번호를 입력할 수 있어야 합니다.
- 이메일이 비어 있으면 에러를 표시해야 합니다.
- 비밀번호가 비어 있으면 에러를 표시해야 합니다.
- 비밀번호는 최소 8자 이상이어야 합니다.
- 비밀번호 확인 값이 다르면 제출할 수 없어야 합니다.
- 회원가입 중 버튼이 비활성화되어야 합니다.
- 이미 가입한 이메일이면 실패 메시지를 보여줘야 합니다.
- 이메일 인증 절차 없이 회원가입 성공 후 대시보드로 이동해야 합니다.

#### 로그인

- 올바른 계정으로 로그인할 수 있어야 합니다.
- 잘못된 계정이면 실패 메시지를 보여줘야 합니다.
- 로그인 성공 후 보호 페이지로 이동해야 합니다.
- 새로고침 후에도 로그인 상태가 유지되어야 합니다.

#### 로그아웃

- 로그아웃 버튼을 제공해야 합니다.
- 로그아웃 성공 후 로그인 페이지 또는 랜딩 페이지로 이동해야 합니다.
- 로그아웃 후 보호 페이지에 접근할 수 없어야 합니다.

### 프로젝트

- 로그인한 사용자는 프로젝트를 생성할 수 있어야 합니다.
- 프로젝트 이름은 필수값이어야 합니다.
- 프로젝트 목록에서 자신이 만든 프로젝트만 보여야 합니다.
- 프로젝트 상세에서 해당 프로젝트의 할 일을 볼 수 있어야 합니다.
- 프로젝트를 수정할 수 있어야 합니다.
- 프로젝트를 보관할 수 있어야 합니다.
- 프로젝트가 없으면 빈 상태를 보여줘야 합니다.

### 할 일

- 로그인한 사용자는 프로젝트에 할 일을 추가할 수 있어야 합니다.
- 할 일 제목은 필수값이어야 합니다.
- 할 일은 하나의 프로젝트에 속해야 합니다.
- 할 일의 상태를 변경할 수 있어야 합니다.
- 할 일의 우선순위를 변경할 수 있어야 합니다.
- 마감일을 입력하거나 수정할 수 있어야 합니다.
- 할 일을 수정할 수 있어야 합니다.
- 할 일을 삭제할 수 있어야 합니다.
- 삭제 후 목록에서 해당 할 일이 사라져야 합니다.

## 16. Supabase 데이터 보안 원칙

로그인 기능을 사용하므로 모든 프로젝트와 할 일에는 user_id가 있어야 합니다.

RLS 정책의 기본 원칙은 다음과 같습니다.

- 사용자는 자신의 프로젝트만 조회할 수 있습니다.
- 사용자는 자신의 프로젝트만 생성·수정·보관할 수 있습니다.
- 사용자는 자신의 할 일만 조회할 수 있습니다.
- 사용자는 자신의 할 일만 생성·수정·삭제할 수 있습니다.
- 할 일을 생성할 때 프로젝트도 현재 사용자의 소유인지 확인해야 합니다.
- 다른 사용자의 ID를 URL에 직접 입력해도 데이터를 볼 수 없어야 합니다.

구현할 때는 화면에서 숨기는 것만으로 충분하지 않습니다. 실제 데이터베이스 정책에서도 사용자 ID를 확인해야 합니다.

## 19. 테스트 시나리오

- [ ] 비밀번호 확인이 다르면 회원가입이 막힌다.
- [ ] 정상적으로 회원가입할 수 있다.
- [ ] 정상적으로 로그인할 수 있다.
- [ ] 잘못된 비밀번호로 로그인하면 에러가 표시된다.
- [ ] 새로고침 후 로그인 상태가 유지된다.
- [ ] 로그아웃 후 대시보드에 접근할 수 없다.

### 프로젝트 테스트

- [ ] 프로젝트 이름이 비어 있으면 생성할 수 없다.
- [ ] 프로젝트를 생성하면 목록에 나타난다.
- [ ] 프로젝트 상세 페이지로 이동할 수 있다.
- [ ] 프로젝트를 수정할 수 있다.
- [ ] 프로젝트를 보관하면 기본 목록에서 숨겨진다.
- [ ] 프로젝트가 없으면 빈 상태가 표시된다.

### 할 일 테스트

- [ ] 제목이 비어 있으면 할 일을 저장할 수 없다.
- [ ] 할 일을 특정 프로젝트에 추가할 수 있다.
- [ ] 할 일 목록과 상세를 확인할 수 있다.
- [ ] 상태를 할 일·진행 중·완료로 변경할 수 있다.
- [ ] 우선순위를 변경할 수 있다.
- [ ] 마감일을 설정할 수 있다.
- [ ] 할 일을 수정할 수 있다.
- [ ] 할 일을 삭제하면 목록에서 사라진다.

### 상태 UI 테스트

- [ ] 요청 중에 로딩 UI가 표시된다.
- [ ] 요청 실패 시 에러 UI가 표시된다.
- [ ] 데이터가 없을 때 빈 상태 UI가 표시된다.
- [ ] 저장 중 버튼이 비활성화된다.
- [ ] 삭제 중 중복 요청이 발생하지 않는다.
